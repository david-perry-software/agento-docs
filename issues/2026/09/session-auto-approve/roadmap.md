## Follow-ups

- Delivery guard false positive: a brace group whose segment names a hook path — `{ shellcheck scripts/hooks/*.sh …; } 2>&1 | tail -5` — is denied with the hook-write reason because `{` becomes the command word; treat `{`, `(`, and `!` as prefixes in `command_word()` and add fixtures (a `scripts/hooks/` change: separate, approval-gated delivery).
- In-repo layout sessions open a bare folder and therefore get no session settings block; consider generating a single-folder `<kind>-<id>.code-workspace` for in-repo sessions so the same block applies (touches `paths`, `session`, `ship`, `close-session`, and the extension's target routing).
- Consider adding `chat.tools.urls.autoApprove` for the fetch tool to the session block if URL approvals turn out to interrupt unattended runs.
